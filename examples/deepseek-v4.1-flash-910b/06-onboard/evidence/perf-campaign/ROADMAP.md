# DeepSeek-V4.1-Flash on 8×910B3 — 战役路线与性能演进

一个模型从"网上有人跑过"到"优化反哺上游"的完整路线。每一步的性能
都标了口径：单流延续口径 = 8K 上下文、512 token 强制长生成、预热 5 次
丢弃后取中位（`decode_probe.py longgen-prompt.json 512`）；精度 =
GSM8K-100 原协议门禁（官方 encoder + 串行 prefill + 数字兜底抽取）。

## 各阶段的"为什么"（技能视角）

- **0-1**（finder / day0 / benchmark / profiler）：先证明"能跑"且知道时间去哪了。
  冷探针 15.1s vs 热 0.94s——一切测量先预热。
- **2**（compute-simulation）：理论不是装饰——它预言"残差里的投机是最大杠杆、
  字节类变体 ±0%、kernel 天花板 ≤17%"，后面每一步都验证了这个排序。
- **3-5**（extreme-perf-campaign P1）：理论排序做实验顺序；每个改动过精度门；
  死胡同（E3）写文档而不是硬啃。E1 的 6.1× 全部来自"让投机真正生效"。
- **6**（P3 算子层）：库→模型流→自写→诚实算术的次序；停止线是算出来的。
- **7-8**（P4/P5）：稳定之后再定价；定价回答"rebase 还是携带补丁"。
  答案：上游 5 周吃掉了 11/12 个补丁的价值，剩下的 1.81× 全在 DRAFT_GRAPH。
- **9-10**（upstream-pr-contribution）：PR 的数字必须是清理版代码跑出来的
  （96.3→116.9，+21%）；内部栈的 174.3 只是参照系，不进 PR。

## 一句话

部署 → 取证 → 理论排序 → 门禁实验 → 诚实停止 → 稳定 → 上游定价 →
最小回传——每一步都有数字，每个数字都有口径。
