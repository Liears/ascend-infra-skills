# model-deployment-runbook

适配战役结束不是交付结束。最后一步是把"在这台机器上跑通了什么"翻译成
"在任何一台同构机器上怎么复现"。本 skill 规定这份文档的结构与纪律。

**触发**：模型适配/性能战役完成，需要输出部署指导书 / handoff / 交付文档。

## 核心纪律（每条都来自真实返工）

1. **零机器硬编码**。读者没有你的目录、镜像、容器名。路径/镜像 tag/容器名/克隆位置
   一律 `<占位符>`（附自选示例）；可以字面保留的只有**客观事实**：官方 tag、版本号、
   sha256 期望值、字节长度、门禁基线、参数。
   写完必须跑 `scripts/check_deploy_doc.py`——它会抓 `/mnt/...`、本机容器名、IP 等硬编码。
2. **镜像给从零构建路径**，不是"用我的镜像"。基底（官方 tag）→ 构建脚本（哪个仓库）→
   增量补丁（从哪个可公开获取的位置）→ `docker commit` 出读者的 tag。
3. **每个数字有口径与日期**。性能锚点写清 workload 形态、预热策略、统计口径；
   精度门禁写数据集、采样参数、基线分数。没有实测的写 `TBD（未验证）`，不编。
4. **排除路线要留证据**。被否掉的替代方案（如"官方原始量化单机装不下：59.5GB/卡无 KV
   余量"）写进决策表——这是读者换环境时重新决策的依据。
5. **坑表写三列**：症状（读者会看到的现象）→ 原因 → 处置命令。症状要能被 grep。

## 文档结构（按 `references/runbook-template.md` 展开）

1. **一页决策表**——权重从哪来 / 要否量化 / 软件版本 / 镜像 / 要否 PR / 命令在哪节
2. **权重获取**——下载命令（断点续传）+ sha256 校验 + 排除路线表 + 目录内容清单
3. **一次性处理**——任何下载后、起服前的手工步骤（拼接/重组/转换），带期望输出字节数
4. **代码与镜像**——clone 哪个仓、构建命令、增量补丁来源与打法、版本事实表
5. **起容器**——完整 `docker run`（设备/驱动注入/缓存目录），缓存"首次为空可复用"要写明
6. **起服**——环境变量 + 一条逐字可用的 `vllm serve`（多行续行，直接可粘贴）
7. **验收**——健康标志（引擎日志里的判据行）→ 预热后探针（预热几条丢几条、健康判读值）
   → 精度门禁（脚本/数据/编码器的获取方式 + 基线分）
8. **已知坑表** + **上游关系**（本流程依赖哪些私有补丁、上游 PR 状态，防止两条线混淆）
9. **参考资料**——所有仓库/文档链接

## 工具

- `scripts/check_deploy_doc.py <doc.md>` —— 部署文档门禁：
  抓硬编码路径（/mnt、/home/<user>、绝对 /tmp、本机容器名样式）、IP（127.0.0.1 除外）、
  缺失章节、未替换的 `TBD`、无口径的裸数字行。输出 PASS/FAIL + 逐条定位。

## 与其他 skill 的关系

- 素材来自 `extreme-perf-campaign`（战役账本、性能锚点）与
  `llm-serving-accuracy-gate`（门禁协议与基线）——文档只引用其产物路径，不复制。
- worked example：`examples/deepseek-v4.1-flash-910b/06-onboard/DEPLOY-1017.md`
  （8×910B3 上的 1017 权重部署指导书，本 skill 结构的完整实例）。

## 红线

- 把本机镜像名/路径当作用户可直接引用的东西写进文档
- 起服命令"示意即可"——必须是逐字可运行
- 验收只写"能跑就行"——无门禁基线的文档不是交付件
